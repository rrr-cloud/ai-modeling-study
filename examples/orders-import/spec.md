# 注文CSVの取り込み 仕様

## 目的
基幹システムが出力する注文CSVを、毎晩DBへ取り込む。

## 入力 / 出力
- 入力: `orders_YYYYMMDD.csv`（UTF-8、ヘッダーあり）
  - 列: order_id, customer_id, amount, status, ordered_at
- 出力: orders テーブルへ upsert し、結果（取り込んだ件数・スキップした件数・対象外の件数）をログに出す
- 呼び出し方: `python -m orders.import_csv <CSVのパス> <DBのパス>`

## 制約
- 10万行を5分以内で処理する
- 既存の `OrderRepository` を使う。スキーマは変えない
- 標準ライブラリのみ使う

## やらないこと
- ほかのテーブルの更新
- `OrderRepository` の既存メソッドの挙動の変更

## 受け入れ基準
- 不正な行はスキップし、行番号をログに出す
- 同じファイルを2回流しても件数が変わらない
- 上の2点を確認するテストが通る

## 決まったこと（質問への回答）

### 不正な行
次のどれかに当たる行は不正とし、スキップする。値は前後の空白を取り除いてから検証する。
- 列の数がヘッダーと合わない
- order_id, customer_id, amount, status, ordered_at のどれかが空
- amount が 0 以上の整数でない（負の数・小数・桁区切り・符号つきは不正）
- status が `paid` / `pending` / `cancelled` のどれでもない
- ordered_at が `YYYY-MM-DD` の形式でない

### 対象外の行（status が cancelled）
- status が `cancelled` の注文は取り込まない。不正な行とは別に「対象外」として件数を数え、結果のログに出す
- 対象外の行は WARNING には出さない
- すでに DB にある注文が `cancelled` で来た場合も、何もしない（消さない・上書きしない）
- 検証を先に行う。`cancelled` の行でも、ほかの値が不正なら不正な行として扱う（スキップして WARNING に出す）

### 件数と行番号
- 取り込んだ件数は upsert した行数（新規と上書きの合計）
- 同じ order_id がファイル内に複数あるときは後の行で上書きし、どの行も取り込んだ件数に数える（対象外の行は上書きしない）
- 行番号はファイル上の行番号（ヘッダーが 1 行目、最初のデータが 2 行目）
- CSV に無い注文は DB から消さない

### 書き込み
- 全行を読んで検証してから、1 回で書き込む。ファイルが途中で読めなくなったときは 1 件も入らない

### ファイル全体のエラー
次の場合は 1 件も取り込まず、エラーをログに出して終了コード 1 で終わる。
- CSV ファイルが無い
- UTF-8 として読めない
- ヘッダーに必要な列名が足りない
- DB ファイルが無い（新しく作らない）

ヘッダーについては次を受け付ける。
- 先頭の BOM
- 列の順番の違い（列名で読む）
- 余分な列（無視する）

### 終了コードとログ
- スキップした行や対象外の行があっても終了コードは 0
- ログは標準エラー出力に `logging` で出す。スキップした行は WARNING、結果は INFO、ファイル全体のエラーは ERROR
- ファイル名は検証しない（渡されたパスをそのまま読む。日付部分は使わない）

### 性能
- 「10万行を5分以内」は手元の計測で確認する。自動テストには入れない
