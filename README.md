# AIに「作って」と頼んだら、ここまでできる。

Claude Code × Blender MCP を例に、AI駆動開発と仕様駆動開発のはじめかたを紹介する、約10分の勉強会資料です。

## 見かた

GitHub Pages で公開しています。ブラウザで開くだけで見られます（インストール不要）。

- `→` / `←` キー（またはクリック・スワイプ）で進む・戻る。項目は1つずつ出て、いま話している所が光る
- `N` キー：話す内容メモ（発表原稿）を下に出す。いま話す段落が光る
- `F` キー：全画面
- [発表原稿](script.html)：全ページの原稿。印刷もできる

## 実験について

指示A・B・C・C＋追加の修正の結果は、毎回、前の会話を知らない新しい Claude Code に指示の文だけを渡して作らせたものです（指示Aは同じ文で4回）。

- 動画の Claude Code 画面の各行は、AIが実際に行った Blender の操作1回ずつに対応しています。載せているコードの行は、AIが書いたコードからの抜粋です。
- Blender の画面は、AIの操作が1回終わるごとに自動で撮影した絵です。撮影のときだけ照明と背景をそろえています（AIが置いた照明や床は撮影中だけ隠しています）。AIが1回の操作でまとめて作った部分は、途中の絵がありません。
- トークン数・操作の回数・時間は、各実験で Claude Code が記録した値です。
- 実験Cの途中で、AIが名前の取り違えから別のシーン（指示B）の物を消し、自分で気づいて戻しています。全部のシーンを1つの Blender ファイルで行った実験の作りも原因の一つです。指示Bの撮影はその前に済んでいます。
- 「回数を重ねると、ガラスのコップになることもあった」は、同じ条件で指示Aをさらに4回試したときの結果です（そのうち3回がガラスのコップ）。
- 「C＋追加の修正」の追加の指示は、資料の作成者が指示Cの結果を見て書いたものです。
- トークンのページの「大雑把に始めて直していく」実験は、新しい Claude Code に「コップを作って」とだけ頼み、指示Cの仕様に届くまで、資料の作成者が結果を見て追加の指示を出したものです（3往復）。この実験だけ、取り違えを防ぐため「作る物の名前に E_ を付ける」を作業ルールに足しています。
- GitHub Copilot の使用量の数え方は、GitHub の発表（2026年4月27日「GitHub Copilot is moving to usage-based billing」）によります。

## 中身

- `index.html` … 資料本体（外部の読み込みなし）
- `script.html` / `script-data.js` … 発表原稿（資料のメモと同じ内容）
- `videos/` … 4本の動画（1920×1080）と、その結果の画像
- `images/` … 表紙の灯台と、その作成途中の画像
